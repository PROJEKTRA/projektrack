### S-0916 String system with ICU MessageFormat and fallback chain

| Field | Value |
|---|---|
| Persona | Employee (Bosnian speaking) |
| Priority | Must |
| Estimate | 18 h (build 10, tests 5, review and docs 3) |
| Sprint | L1 Foundation (18-21 Nov) |
| Dependencies | Repository (Phase 0) |
| Modules | core |
| Edition | Community |
| Reviewers | ux, qa |

**Story:** As an employee, I want every text in the product, in emails and in documents to appear in my language with correct plural forms, so that I can work without guessing.

```gherkin
Scenario: Identifiers and one layer for backend and frontend
  Given the string "timesheets:hours_booked" defined in en and bs
  Then Laravel validation messages, Vue components, emails, PDF, DOCX and XLSX exports resolve it through the same layer
  And the frontend loads resolved strings per language as a versioned, cached bundle

Scenario: Bosnian plural rules
  Given the string "{count, plural, one {# sat} few {# sata} other {# sati}}"
  Then 1 renders "1 sat", 2 renders "2 sata", 5 renders "5 sati", 21 renders "21 sat"

Scenario: Fallback chain without raw keys
  Given a string missing in the user's language "de" and in the tenant language
  Then the bs text is shown, otherwise the en text
  And the missing string is logged once per identifier and language
  And a raw identifier is never shown to the user

Scenario: Default locale
  Then a new installation defaults to bs
```

### S-0918 Admin language customization

| Field | Value |
|---|---|
| Persona | Tenant admin |
| Priority | Must (cut candidate, see README) |
| Estimate | 14 h (build 8, tests 4, review and docs 2) |
| Sprint | L1 Foundation (18-21 Nov) |
| Dependencies | S-0916 |
| Modules | core |
| Edition | Community |
| Reviewers | ux, security, qa |

**Story:** As a tenant admin, I want to override any string in any language through the UI, so that the product uses my company's terminology (for example "Activity report" instead of "Service report").

```gherkin
Scenario: Override a string per tenant
  Given the string "reports:service_report" is "Service report" in en
  When the admin overrides it for the tenant with "Activity report"
  Then all screens, emails and exports of that tenant show "Activity report"
  And other tenants still see "Service report"

Scenario: Search and compare
  Then the admin can search by identifier or text, filter by module, and see original, translation and override side by side

Scenario: Overrides survive updates and are flagged
  Given an override exists and the en source text changes in an update
  Then the override is kept and flagged "source changed, please review"

Scenario: Safe output
  Then an override containing HTML or script is rendered as text

Scenario: Valid texts only
  Then an override with invalid ICU syntax or placeholders the en source does not have is refused with the reason
  And legal notices (identifiers containing "legal_notice") need the permission tax.legal_notice.override
```

Implementation note (18.11.2026): Admin > Languages > Edit texts (`/admin/languages/{locale}/strings`). Filters: all, own texts, not yet translated, original changed; 50 per page. Removing an own text restores the shipped text (for a copied language: the text of the language it was copied from). Tenant scope only; instance-wide overrides and an inline translation mode follow later.

### S-0921 Language packs and preview languages

| Field | Value |
|---|---|
| Persona | Tenant admin |
| Priority | Must |
| Estimate | 10 h (build 5, tests 2, review and docs 3) |
| Sprint | L1 Foundation (18-21 Nov) |
| Dependencies | S-0916 |
| Modules | core |
| Edition | Community |
| Reviewers | qa |

**Story:** As a tenant admin, I want to see which languages are complete and install or update language packs, so that I know what my users will get.

```gherkin
Scenario: Completeness and preview label
  Then Admin > Languages lists bs, en, de, fr, es, ar and fa with completeness in percent
  And fr, es, ar and fa are labeled "Preview (machine translated)"
  And Hebrew is not offered

Scenario: CLI
  When the operator runs "projektrack lang:install fr" or "projektrack lang:update"
  Then the pack is installed or updated without a software release
  And existing admin overrides are kept

Scenario: Import and export
  Then a pack can be exported and imported as XLIFF or JSON

Scenario: Deactivate a language
  Given 3 users of the tenant chose "en"
  When the admin deactivates "en" after a confirmation that names the 3 users
  Then "en" is no longer offered in the profile and those users see the tenant language
  And their choice is kept, so they see "en" again once it is reactivated
  And the tenant language cannot be deactivated, and en stays the last fallback

Scenario: Copy a language to localize it into a new one
  When the admin copies "bs" into "hr" named "Hrvatski"
  Then "hr" starts with every string of "bs", marked "not yet translated" (0 % translated)
  And users of the tenant can choose "Hrvatski", formatted with the plural rules of hr
  And strings added by a later update fall back to "bs"
  When the admin exports "hr", translates the file and imports it
  Then the imported strings are shown and count as translated
  And a file with one invalid message (ICU syntax, unknown identifier, placeholders the en source does not have) is refused as a whole, with every reason listed
  And other tenants see neither the language nor its strings
```

Implementation note (18.11.2026): deactivation and copy are per tenant (`tenant_languages`); the strings of a copy are tenant `string_overrides` of the new locale. Import and export cover own languages as JSON; XLIFF and pack install follow with the language pack work.
